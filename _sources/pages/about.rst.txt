========
About Me
========

I'm a builder. Take a raw requirement — a smoke alarm system stalled for a year,
a gym franchise with no centralized ledger, an accounting engine that needs to
talk to AI agents — and I'll force it into a structured, working state. My
instinct is always the same: if it can be automated, automate it. If it can be
accelerated with agents, build them. Doing things manually is a failure of
imagination.

**SulfurBook** exists because I wanted an immutable double-entry ledger that
AI agents could audit directly — not a dashboard, an API for agents. **Ruslan's
Studio** exists because a multi-branch gym had no way to guarantee financial
integrity across locations; I gave them append-only ledgers and RBAC portals.
**AgniStop** exists because a LoRa sync bug had the hardware team stuck for a
year; I read the datasheets, rewrote the firmware layer, and shipped it in five
weeks.

I don't just write code. I build systems that replace manual overhead.

How I Started
=============

I didn't start as a software engineer. I started in **graphic design** with a
handful of Photoshop skills and no real plan. Clients came to me with requests
I didn't know how to fulfill — and I figured it out as I went. Every project
taught me something: what worked, what didn't, what to charge, what to avoid.
I learned more from client feedback than from any tutorial.

That pattern never changed. When I moved into **electronics**, I bought a
breadboard and some components and started building. I entered three line-
follower robot competitions — never won a single one, but each failure taught
me more about motor drivers, sensor tuning, and PID control than any textbook
could. When I wrote my first **firmware**, I read datasheets until the concepts
clicked. When I took on **full-stack** projects, I shipped something that
worked and refactored it after. Every transition followed the same playbook:
start with what you have, get feedback, improve, repeat.

At some point the skills compounded. Graphic design taught me visual structure.
Electronics taught me physical constraints. Code gave me leverage. Now I can
design a brand identity, write a LoRa firmware sync layer, architect a FastAPI
deployment, and build an RAG-based AI agent — all production, all shipped.
I own the full stack, from transistor to cloud API.

How I Work
==========

- **Pragmatic over perfect.** I ship. I refactor later. A working system today
  is worth more than a perfect one next month.
- **Zero tolerance for manual repetition.** If I've done it twice, I'm
  automating it the third time — scripting, agents, CI, whatever it takes.
- **I say what I mean.** No corporate padding. If I can do it, I'll tell you
  the timeline. If I can't, I'll tell you why. If there's a better way than
  what you asked for, I'll argue for it.

The Other Side
==============

Honest self-assessment:

- **Maintenance drains me.** Building a new architecture energizes me;
  sustaining a legacy codebase wears me down. I'll do it, but I won't pretend
  to love it.
- **Low tolerance for bureaucracy.** Too many meetings, too much process, too
  little output — I'll check out.
- **I overextend.** Day job, side projects, ventures, family, fitness — my
  ambition regularly exceeds the 24-hour budget. I'm aware of it. I'm working
  on it.

If you need someone to sit in status meetings all day and polish JIRA tickets,
I'm not your person. If you need someone to take a hard problem, figure out
what actually matters, and deliver — let's talk.
